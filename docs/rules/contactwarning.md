# 供应商联系人预警规则与迁移差异

来源：wz-mszb-server.jar SHA-256 50ce53cac1e5110216d72157b0fd2e766db0cebe5a77d3248d8d048a87fc2ff8；CFR 0.152 恢复 WarnConfirmEcp 的 findCrossBidderDuplicates/checkField/getUnitInfo/getAllData。

在同一分标和分包内，比较不同供应商的固定电话、电子邮件、传真号码、邮政地址、手机号码及投标人联系人姓名。非空字段相同即产生对应预警。邮政地址必须含数字或“号”才参与相同比较；空值不参与；同一供应商重复出现不构成跨供应商预警。

原算法确实把同名联系人作为预警，因此修正之前计划中“同名不直接视为违规”的措辞理解：姓名相同仍产生人工核验线索，但不自动判定违规。保留源文本，不擅自去除电话区号、空格或大小写；供应商按源值匹配。

已核实缺陷：getUnitInfo 把电子邮件和传真都读自第 J 列；包内供应商联系人模板的传真表头实际位于 K 列。新实现按明确表头读取传真，邮件与传真分别验证。

输出改变：开发版按“分标、包、供应商对、字段、相同内容”逐项列出，保留包01等源标识；未复刻原程序将连续包号及多原因压缩到单行的显示格式。合并排版尚待补齐，不能把当前输出称为与原版逐单元格一致。原文件不修改，未知供应商会产生提示。

验证：6 个纯规则测试和2个真实xlsx输入输出测试，覆盖分标分包范围、重复行、空值、地址过滤、同名、传真与邮件列分离、前导零、缺表头拒绝输出。
