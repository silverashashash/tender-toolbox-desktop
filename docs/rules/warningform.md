# 预警事项确认单

来源：原JAR静态反编译`RPAApi.warnConfirmForm`→`WarnConfirmForm.generateWarnConfirmFormTemplate`，可读证据`outputs/analysis/warning-form-readable.java`。未运行原网站。

输入风险提示表、标包分组表、开标项目信息表。按表头名称识别（原风险表第2行表头也可），读取首sheet。风险表包含分标/包/投标人、注册地址/企业联系方式/邮箱及各“是否相同”标记，标记须为是/否。采用原版同一标包、不同投标人、完全相同的标记组合，且被标记字段值全部相等的匹配规则。已标记相同但字段为空/占位符拒绝。

同一预警事项的供应商按技术组和商务组分别生成Word，项目、分标、组别、完整供应商名单及具体原因相同的记录合并包号；输出一个ZIP。缺分组、开标记录或标包项目信息冲突均报错，不悄悄漏生成。代码/名称用结构化键，Word文件名采用“预警事项确认单(预警内容)-标段-包号-涉及的供应商名称-批次号xx组.docx”，多个包号、供应商或预警内容用“、”连接；批次号取开标信息中的采购项目编号，组名来自分组表，不重复追加“组”。清理Windows不支持的路径字符，同名文件追加序号避免覆盖。

模板：按用户要求使用原程序包内的预警事项确认单.docx，保留原版格式及“未发现该两家应答人应答文件异常一致”等固定文字，只替换项目、标包、企业、预警事项、评审组和日期占位符。默认日期采用yyyy年MM月dd日；用户填写的日期原样保留。目前未提供自定义Word模板替换。原风险工作簿第二张基本信息表不再必需（生成原因实际使用第一张表中的具体值）。按标包关联开标元信息而非只取分标第一条。全部无匹配时生成说明文件并提示，不能据此认定人工复核无异常。

确认单日期留空使用本机当天日期，可手填。模板日期不涉及授权或失效检查。测试覆盖分组生成、包号归并、原因、签字待填和缺组拒绝；真实风险/分组文件尚待业务验证。

## 原始风险表表头兼容（2026-10-23）

支持首两行合并表头：按单列纵向合并区域读取表头锚点，数据从完整表头之后开始；不将横向分组标题展开为字段，也不填充数据区空值。风险表中的“分包编号”（实际内容如“包1”）映射到分包名称，“投标厂商名称”映射到投标人；该映射仅限风险表，开标表仍读取“分包名称”，避免与其真实编号列混淆。原单行填写模板继续可用。

对用户目录的四份原始风险表只读验证，记录数分别为520、81、19、104。两份20260608文件与各自开标表、用户分组表完整运行通过；注册地址、企业联系方式、邮箱三项相同标记全部为“否”，因此当前工具未生成确认单。此结果不表示其他风险项目没有预警。

## 多企业确认单（2026-10-29）

同标包按三项预警标记组合及所有启用项的具体值分组，至少两家不同企业时生成一单；非启用项的值不参与分组。企业名单去重，技术/商务组分别输出。跨包仅在项目、分标、评审组、风险内容及完整企业名单均相同的情况下合并包号，防止误扩大某企业涉及的包范围。企业数量和名称动态填写；超过两家时原模板“该两家应答人”替换为实际数字，其余版式保留。现有风险类型及标记组合匹配口径不变。
